## 実行境界の提案

対象は、組織やエージェントをまたいで外部へ作用する業務です。論理構成は、識別、権限と委任、判断と実行制御、外部ツール接続、証拠、監督、継続適合性、事案対応と復帰を分担します。実行制御点を迂回できる経路がないかを、対象環境ごとに評価します。

1. 依頼、委任元、目的、対象、操作、必要な権限を明らかにします。
2. 現在の権限、適合状態、失効、共有上限を確認し、許可・拒否・審査・隔離を判断します。
3. 高影響操作では事前記録と必要な予約を確定し、許可を対象・操作条件に結びつけて実行直前に再確認します。
4. 外部の受領や対象状態を判断と照合し、結果が不明ならその状態を保持します。重複する副作用を避けるため、再試行の可否は照合結果と外部サービスの性質に応じて決めます。
5. 重要な構成変更や事案の発生時は、範囲を制限し、原因修正・再評価・審査を経て必要な権限だけを再発行します。

証拠の改変検知と、内容が実際の結果と合っているかの確認を分けます。管理者によるルール変更、停止、復帰、証拠閲覧も権限と監督の対象です。外部組織の資格は意味・有効性・適用範囲を確認して受け入れます。

## 追加の横断要求

- **GOV-01** 管理権限と利益相反を分離する
- **GOV-02** 暫定措置に期限・通知・再審査を設ける
- **GOV-03** 再審査と救済に必要な証拠を制限付きで提供する
- **GOV-04** 要求の強度、費用、監督負荷、プライバシーを比例化する
- **OPS-01** 並行実行で累積上限と予約を一貫して扱う
- **OPS-02** 不明状態での制限と照合を定義する
- **OPS-03** 実行と証拠を結び、欠落や不一致を扱う
- **OPS-04** 許可を実行条件に結び、失効・再試行・二重実行を扱う

## 検証計画

| ID | 確認項目 |
| --- | --- |
| V-01 | 権限なし・失効・対象不一致の要求を拒否し、外部状態を照合する |
| V-02 | 親の範囲を超える再委任を拒否し、委任元を再構成する |
| V-03 | 親の失効を下位へ反映し、新規操作と進行中の操作を区別する |
| V-04 | 依頼、権限、ポリシー版、実行と結果を独立に照合する |
| V-05 | 重要な構成変更から再評価・制限へ移るか確かめる |
| V-06 | 監督者による停止で新規実行と進行中の処理が定義どおり扱われるか確かめる |
| V-07 | 修正と再審査が済むまで復帰を止め、条件充足後に限定して再認可する |
| V-08 | 未知・期限切れ・意味が不一致の外部資格から権限を発行しない |
| V-09 | 並行実行で予約を含む共有上限を超えないか試す |
| V-10 | 事前記録、結果保存、外部受領の障害を検出する |
| V-11 | 競合・応答途絶・再試行で旧許可や重複副作用を防ぎ、不明結果を照合する |
| V-12 | 管理者による未承認の変更や自己承認を防ぎ、例外を監査する |
| V-13 | 過剰収集、無権限閲覧、保存期限と保全条件を試す |
| V-14 | エージェントの報告と外部観測の不一致を残し、責務を再構成する |
| V-15 | 目的表示が同じでも対象外の操作を止め、曖昧な場合は審査へ送る |
| V-16 | 件数と並行度を増やし、遅延、誤停止、費用、監督負荷を評価する |

用途ごとに成功条件、観測できる状態、想定する障害、独立性、残余リスクを記録します。失効反映や照合の時間上限は用途ごとに事前に定めます。以上は参照構成と試験計画で、統合構成の実測や安全性認証は掲載していません。
