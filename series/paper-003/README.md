## 判断と実行を分ける

エージェントが操作を提案したら、ポリシー判断点（PDP）が主体、委任、目的、対象、リスク、構成の適合性、失効状態を評価します。実行制御点（PEP）は許可・拒否・審査などの判断を操作の直前で強制します。影響の大きい操作は実行アダプターを経由させ、実行制御点を通らない経路の有無を検証対象に含めます。

証跡には、意図、委任と権限、判断とポリシー版、対象と観測結果、人の介入、事案対応、復旧を関連づけます。認可の記録と実行後の観測を照合し、欠落や不一致も扱います。識別、実行、証跡、監督は論理上の責務として分け、配置や独立性は実装ごとに評価します。

## 要求・設計・検証の対応

| 第002論文の要求領域 | 主な制御点 | 検証する問い |
| --- | --- | --- |
| ID | 識別・状態解決 | 無効な識別情報で高影響操作を試し、拒否を確認する |
| AUTH | 権限とポリシー判断・強制 | 権限のない外部操作を阻止する（V-01） |
| DEL | 委任検証 | 子の権限が親の範囲を超えないか試す（V-02） |
| PUR | 目的と対象を評価するポリシー | 目的外の操作を拒否または審査へ送る |
| CON | 構成管理と継続適合性 | 重要な変更から再評価へ移るか試す（V-05） |
| EVD | 証跡 | 操作から委任・権限・判断・結果を再構成する（V-04） |
| HUM | 人の監督 | 監督点から実行を止められるか試す（V-06） |
| INC | 事案対応 | 異常検知から封じ込めへ移れるか確かめる |
| REV | 失効と実行直前の確認 | 親の失効が下位委任に伝播し、新規操作を止めるか試す（V-03） |
| REC | 復旧・再認可 | 修正と審査を経ずに旧権限が復活しないか試す（V-07） |
| ACC | 役割と証跡 | 誰が委任・実行・監督したかを区別する |
| INT | 相互運用ゲートウェイ | 未知の外部資格が検証なしで権限にならないか試す（V-08） |

上表の V-01〜V-08 はこの論文の検証案です。技術提言では、別文書の同じ番号として参照します。

## 信頼境界と最小PoC

人・組織からエージェントへの委任、子エージェントへの再委任、判断点から実行点への許可伝達、外部対象への作用、証跡の受け渡し、組織をまたぐ資格の受け入れで、それぞれ何を再確認するかを定めます。最小PoCでは、識別、権限、判断と強制、ツール接続、証跡、監督、失効と復旧の七つの論理機能を対象にできます。

実行時には、権限の範囲、構成の変更、失効を確認します。問題があれば範囲縮小や停止へ進み、原因の修正・再評価・審査を経て、必要な権限だけを再付与します。

## 検証範囲

本稿は参照設計です。最初の評価では、許可と拒否の両方、証跡の欠落、構成変更、失効、停止と復帰を模擬環境で確認し、観測できた範囲を示します。ここに挙げた項目は試験計画で、統合実装の実測結果は本稿に含みません。
