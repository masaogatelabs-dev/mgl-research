## 問いと方法

社会に広く普及した技術の安全を、製造者・利用者・インフラの運用者・公的な制度はどのように分担してきたか。日本の交通制度の公的資料を読み、制度が果たした機能を抽出します。その機能をAIの既存の取組と比較し、複数の組織やプラットフォームをまたぐときに残る問いを整理します。

## 歴史資料から抽出した機能

警察庁の資料では、戦後の交通ルールの整備、1960年の道路交通法、1970年の交通安全対策基本法と、その後の複合的な対策をたどれます。国土交通省は、自動車登録と、車両の安全・環境基準への適合を確認する検査の役割を分けて説明しています。両資料を、責務の分担と、利用中の変化への対応という観点から読みます。[警察庁](https://www.npa.go.jp/hakusyo/h29/honbun/menu.html) · [国土交通省](https://www.mlit.go.jp/common/001252345.pdf)

| 自動車社会の仕組み | 抽出する機能 | AI社会に引き継ぐ問い |
| --- | --- | --- |
| 登録・車両番号 | 識別と責任関係への接続 | 操作主体と委任元を後からたどれるか |
| 免許・行政処分 | 適格性と参加制限 | 何を委ねられ、どの条件で権限が失効するか |
| 検査・点検 | 継続適合性 | モデルやツールの変更後も評価が有効か |
| 交通規則・取締り | 共通条件と実施 | 組織をまたいでも目的外の操作を制御できるか |
| 道路設備・教育・事故分析 | 環境整備、能力形成、証拠の還流 | 利用環境と人の監督を整え、観測結果を次の改善に使えるか |

## AIへの適用と類比の限界

製品側で改善できる安全性と、共有環境で複数の主体が担う安全を分けて考えます。AIにも組織レベルのリスク管理や、エージェントの識別・認証に関する標準化の取組があります。課題は、それらを委任、操作の制御、事故時の説明へどうつなぐかです。[NIST AI RMF](https://www.nist.gov/itl/ai-risk-management-framework) · [NIST AI Agent Standards Initiative](https://www.nist.gov/news-events/news/2026/02/announcing-ai-agent-standards-initiative-interoperable-and-secure)

デジタルエージェントは複製・更新・再委任ができ、複数のツールにまたがって操作できます。そのため、制度の名称をそのまま移すと、識別の粒度や影響の広がりを捉え損ねます。この比較からは機能に関する仮説を導きます。個々の交通対策の因果効果や、AIへの移植効果は、この資料比較だけでは測定していません。

## 制度形成の時間圧縮

技術能力・配備・相互接続の変化が、リスクを観測して合意形成し、制度を更新する速度を上回る可能性を、研究仮説として置きます。第002論文では、先に試せる要求を定め、事故や実証から得た証拠を要求の見直しに戻す方法を扱います。
